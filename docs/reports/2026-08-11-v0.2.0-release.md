# FoamPilot v0.2.0 发布与验证记录

日期：2026-08-11

## 发布结论

`v0.2.0` 是 FoamPilot 的本机内部研发基线，覆盖 Desktop 交互式求解、Runtime 可配置化和
执行策略审计。本版本不是跨机器产品交付证明，也不是完成私有资产拆分后的公开发行包。

版本由 `foampilot.__version__` 单点声明，并由 setuptools 写入 wheel 元数据：

```text
package version = 0.2.0
wheel metadata version = 0.2.0
git tag = v0.2.0
```

## 确定性与 Desktop 门禁

完整测试：

```text
QT_QPA_PLATFORM=offscreen PYTHONPATH=src \
  /home/edwin/feal-venv-py312/bin/python -B -m pytest \
  -q -p no:cacheprovider tests

730 passed, 10 skipped in 23.34s
```

Desktop 专项测试：

```text
45 passed, 1 skipped in 1.56s
```

skip 项包括需要显式外部环境或真实模型调用的 opt-in gate，不等价于失败，也不能记作通过。

wheel 被安装进 `/tmp` 下的新虚拟环境，并从源码树之外执行。由于验证环境不能访问网络，临时
环境只读复用了现有 Python 3.12 环境中的第三方依赖；`foampilot.__file__` 经检查来自新虚拟环境
的 `site-packages`，不是仓库源码。以下检查通过：

- `foampilot.__version__` 与 distribution metadata 均为 `0.2.0`；
- CLI `--help` 可用并包含 `desktop`；
- `FoamPilotMainWindow` 可从安装后的 wheel 导入；
- 显式 OpenFOAM root、`trusted_host` 的 preflight 返回 `PASS`。

这属于源码树隔离的 wheel smoke，不是无依赖缓存的联网安装证明，也不是第二台机器验证。

## 本机 Foundation OpenFOAM v10 门禁

冻结的非 tutorial plan 在本机 `trusted_host` 策略下重新执行，并同时验证 low-risk fallback 与
dynamic-code 阻断：

```text
2 passed, 5 deselected in 3.46s
```

该证据表明本次 revision 的本机 OpenFOAM 最小闭环仍可运行。它只证明 solver completion 与
对应公开验证；不等于 qualification、网格无关性或工程适用性。

`sandbox_required` preflight 在当前 Codex namespace 中返回：

```text
status = BLOCKED_ENVIRONMENT
failure.code = SANDBOX_REQUIRED_UNAVAILABLE
sandbox_probe.failure_code = NAMESPACE_UNAVAILABLE
```

该结果证明 required 模式没有静默回退 host，但不能记作 sandbox 实机通过。

## 未完成门禁

当前没有第二台干净 Ubuntu + Foundation OpenFOAM v10 机器，以下工作明确保持未验证：

- 从 wheel 独立安装全部依赖；
- runtime 自动发现与 preflight；
- 自然语言到真实 OpenFOAM 求解；
- Desktop 原生显示服务器、Qt xcb/Wayland 和交互实机门禁。

在这些门禁完成前，只能称 `v0.2.0` 为本机内部研发基线。

## 资产分发审计

当前 wheel 共 297 个文件，其中包含：

- 55 个 Knowledge 文件；
- 25 个 Skill 文件；
- 85 个 qualification data 文件。

因此本版本尚未实现 Knowledge、Skills 和 evaluator 的公开/私有拆分。详细后续边界见
[公开与私有资产分发边界](../design/distribution-asset-boundary.md)。在完成分类和构建泄漏门禁
前，不应把该 wheel 上传到公共包索引或公开 Release。
